# Purpose
This Python file is an Alembic migration script used to manage database schema changes for a project that utilizes SQLAlchemy and SQLModel. The script defines both an `upgrade` and a `downgrade` function, which are standard in Alembic migrations to apply and revert changes, respectively. The `upgrade` function creates three database tables: `contentprocessingsession`, `contentmetadata`, and `chunk`. These tables are designed to store information about content processing sessions, metadata related to content, and chunks of text with optional vector embeddings, respectively. The script also ensures that necessary PostgreSQL extensions, such as `vector` and `uuid-ossp`, are available, which are crucial for handling vector data types and UUID generation.

The migration script is part of a broader database version control system, allowing developers to track and apply changes to the database schema in a controlled manner. It includes the creation of indexes on specific columns in the `contentmetadata` table to optimize query performance. The use of UUIDs as primary keys and foreign keys indicates a design choice for unique identification across distributed systems. The inclusion of a vector column in the `chunk` table suggests that the application may involve machine learning or data processing tasks that require vector representations of text data. Overall, this script is a critical component of the database management strategy, ensuring that the database schema evolves in sync with the application's requirements.

# Functions

---
### downgrade 
The `downgrade` function reverses database schema changes by dropping specific tables and indexes.
- **Inputs**:
    - None
- **Control Flow**:
    - The function begins by dropping the 'chunk' table using `op.drop_table`.
    - It then drops the index on 'workspace_id' in the 'contentmetadata' table using `op.drop_index`.
    - Next, it drops the index on 'relative_path' in the 'contentmetadata' table using `op.drop_index`.
    - It proceeds to drop the index on 'codebase_id' in the 'contentmetadata' table using `op.drop_index`.
    - The function then drops the 'contentmetadata' table using `op.drop_table`.
    - Finally, it drops the 'contentprocessingsession' table using `op.drop_table`.
- **Output**:
    - The function does not return any value; it performs operations to modify the database schema.


---
### upgrade 
The `upgrade` function applies database schema changes using Alembic to create tables and indexes necessary for content processing and metadata management.
- **Inputs**:
    - None
- **Control Flow**:
    - Execute SQL command to create the 'vector' extension if it does not exist.
    - Execute SQL command to create the 'uuid-ossp' extension if it does not exist.
    - Create a table named 'contentprocessingsession' with columns for 'id', 'code_revision', and 'arguments', and set 'id' as the primary key.
    - Create a table named 'contentmetadata' with columns for 'id', 'workspace_id', 'codebase_id', 'content_type', 'relative_path', 'misc_metadata', and 'content_processing_session_id', with 'id' as the primary key and a foreign key constraint on 'content_processing_session_id'.
    - Create indexes on 'contentmetadata' for 'codebase_id', 'relative_path', and 'workspace_id'.
    - Create a table named 'chunk' with columns for 'id', 'content_metadata_id', 'text', 'text_embedding_3_small', and 'chunk_number', with 'id' as the primary key and a foreign key constraint on 'content_metadata_id'.
- **Output**:
    - The function does not return any value; it performs database schema modifications.
