# Purpose
This source code file is an Alembic migration script designed to modify the database schema by altering foreign key constraints on the `v2_primary_asset_tag` table. The script provides narrow functionality, specifically focusing on changing the behavior of foreign key relationships to include cascading deletions. In the `upgrade` function, it removes existing foreign key constraints and creates new ones with the `ondelete="CASCADE"` option, ensuring that deletions in the referenced tables (`tags` and `v2_primary_asset`) will cascade to the `v2_primary_asset_tag` table. The `downgrade` function reverses these changes, restoring the original foreign key constraints without the cascade option. This script is part of a version-controlled database migration process, facilitating schema evolution in a controlled manner.

# Functions

---
### downgrade 
The `downgrade` function reverses database schema changes by removing and recreating foreign key constraints without cascade delete options.
- **Inputs**:
    - None
- **Control Flow**:
    - The function starts by dropping two foreign key constraints from the 'v2_primary_asset_tag' table.
    - It then recreates these foreign key constraints, linking 'tag_id' to 'tags.id' and 'primary_asset_id' to 'v2_primary_asset.id', without specifying cascade delete options.
- **Output**:
    - The function does not return any value; it performs schema modifications on the database.


---
### upgrade 
The `upgrade` function modifies the database schema by dropping existing foreign key constraints and creating new ones with cascade delete behavior.
- **Inputs**:
    - None
- **Control Flow**:
    - The function begins by dropping two existing foreign key constraints on the `v2_primary_asset_tag` table: `v2_primary_asset_tag_primary_asset_id_fkey` and `v2_primary_asset_tag_tag_id_fkey`.
    - It then creates a new foreign key constraint on the `v2_primary_asset_tag` table linking `tag_id` to the `id` column of the `tags` table, with the `ondelete` option set to `CASCADE`.
    - Another foreign key constraint is created on the `v2_primary_asset_tag` table linking `primary_asset_id` to the `id` column of the `v2_primary_asset` table, also with the `ondelete` option set to `CASCADE`.
- **Output**:
    - The function does not return any value; it performs schema modifications on the database.
