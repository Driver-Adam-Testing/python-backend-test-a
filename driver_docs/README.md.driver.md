# Content Summary
The provided document is a guide for developers working with the Driver AI Monorepo, focusing on maintaining code quality and testing infrastructure changes. It outlines the setup and usage of pre-commit hooks and the Ruff linter to ensure code consistency across the codebase. Developers are instructed to install pre-commit globally using Python or Homebrew and then install the hooks defined in the `.pre-commit-config.yaml` file. These hooks automatically run Ruff and other linters during commits to maintain code quality. Additionally, developers can manually run pre-commit hooks on all files to ensure compliance with code standards, though this may result in numerous changes.

The document also addresses testing infrastructure changes using the AWS Cloud Development Kit (CDK). Due to the lack of fully automated infrastructure, a `test-in-dev` CDK stack is provided for testing additions to the infrastructure. This stack is manually deployed and can be customized for different environments by modifying the `test_in_dev_stack.py` file and using the `DEPLOYMENT_ENVIRONMENT=test-in-dev cdk deploy` command. The environment variable `DEPLOYMENT_ENVIRONMENT` is mapped to different stacks in the `cdk_app.py` file, allowing for customization of test environments.

The document includes guidance on using AWS constructs and stacks, emphasizing that constructs should represent logical units of an application, while stacks should describe how these constructs are composed and connected for deployment. This approach enhances the reuse potential of infrastructure and provides flexibility in deployment scenarios.
